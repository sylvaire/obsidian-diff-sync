# Diff Sync (WebDAV)

[English documentation](README.md)

Obsidian 差分同步插件：通过 WebDAV 只传输**发生变化的数据块**，并保留冲突双方的内容。

支持坚果云、Nextcloud、ownCloud、Synology、群晖、自建 WebDAV 等。

## 特性

| 特性 | 说明 |
| --- | --- |
| **块级差分** | 基于内容定义分块（CDC）。改一段 200 字的笔记，只上传约 8 KB，而不是整个文件 |
| **重命名零成本** | 按内容寻址，改名/移动文件不产生任何传输 |
| **冲突副本** | 两端同时改同一文件时，按时间或大小选出主文件，另一版本存为 `xxx.conflict-<时间>-<设备>.md` |
| **删除双向传播** | 并带误删保护：单次删除超过 25% 文件会中止 |
| **可选端到端加密** | AES-256-GCM，口令派生密钥（PBKDF2 210k），服务端只看到密文 |
| **本地历史快照** | 覆盖下载前把旧版本存入 `.diff-sync-history/`，默认保留 20 份 |
| **双语界面** | 跟随 Obsidian 语言：中文环境显示中文，其他环境默认英文 |

## 安装

需要桌面版 Obsidian 1.13.0 或更高版本。

### 手动安装

1. 把 `main.js` 和 `manifest.json` 复制到：

   ```
   <你的库>/.obsidian/plugins/diff-sync-webdav/
   ```

2. 在 Obsidian 中打开 **设置 → 第三方插件**，点 **刷新**，然后启用 **Diff Sync (WebDAV)**。

### 从源码构建

```bash
npm install
npm run build      # 产出 main.js
npm test           # 24 个核心测试 + 插件加载测试 + 端到端测试
```

## 配置

打开 **设置 → Diff Sync (WebDAV)**：

| 选项 | 示例 |
| --- | --- |
| 服务器地址 | `https://dav.jianguoyun.com/dav/obsidian-sync` |
| 用户名 | 你的邮箱 |
| 密码 | **应用密码**（坚果云必须用这个，不是登录密码） |
| 远端子目录 | `diff-sync`（多台设备须一致） |

填好后点 **测试连接** 验证读写。

### 坚果云

1. 网页版 → 右上角头像 → **设置** → **安全选项** → **添加应用密码**
2. 服务器地址：`https://dav.jianguoyun.com/dav/<你的库名>`
   —— 一定要带上一级目录名，只填 `https://dav.jianguoyun.com/dav/` 会把整个网盘当同步根！
3. 用上一步生成的应用密码作为密码
4. 把**并发请求数调到 2**（坚果云按请求次数限流，并发高了会被暂时封禁）

实测数据（坚果云真实账号）：

| 操作 | 传输量 |
| --- | --- |
| 82 KB 笔记改 1 行 | 上传 2851 字节（3.4%），节省 96.6% |
| 首次上传 3 个文件 | 94 KB |
| 20 个文件批量上传 | 49 个分块 / 33 秒 |

**注意**：坚果云在高频请求后会返回 503 并封禁一段时间。插件已内置请求节流
（默认每 120ms 一个请求）与长退避重试；自 0.1.7 起每个远端目录只探测一次，
且不超过平均分块大小的文件只上传一个分块，首次同步的请求数已大幅下降。

### Nextcloud / ownCloud

服务器地址形如 `https://your.cloud/remote.php/dav/files/<用户名>/obsidian`。

## 使用

### 侧边栏同步面板

右侧边栏有一个 **Diff Sync 面板**，上面就是「立即同步」按钮：

- 未配置时会显示配置提示，按钮置灰
- 同步中按钮变「同步中…」并出现「取消」按钮
- 下方实时显示当前阶段（扫描 / 下载 / 上传 / 清理）与进度条
- 同步结束后显示上传 / 下载 / 删除 / 冲突数量、耗时、差分节省比例
- 有冲突副本或错误时在面板里直接列出文件名

打开方式：命令面板 → `Diff Sync: 打开同步面板`，或点击左侧栏 ⚡ 图标。
若希望启动时自动打开，在设置里打开「启动时打开同步面板」。

### 其他触发方式

- 左侧栏 ⚡ **立即同步** 图标
- 命令面板 → `Diff Sync: 立即同步`
- 点击底部状态栏的 `⇅` 图标

状态栏会显示 `↑2 ↓1 · 1.2s` 这样的摘要，悬停可见详情。

### 命令

| 命令 | 用途 |
| --- | --- |
| 打开同步面板 | 在右侧边栏打开带同步按钮的面板 |
| 立即同步 | 普通同步，用 mtime 快速跳过未改文件 |
| 完整重新扫描并同步 | 忽略 mtime 缓存，逐个文件重新哈希（怀疑状态错乱时用） |
| 取消当前同步 | 中止进行中的同步 |
| 显示同步日志 | 查看最近同步记录 |
| 清空本地分块缓存 | 释放磁盘空间，下次同步按需重传 |
| 清空本地历史快照 | 删除 `.diff-sync-history/` |

## 同步是怎么工作的

### 1. 分块

文件被切成约 8 KB 的块。**关键点：切分边界由文件内容决定**，而不是固定偏移。

```
文件 A:  [块1][块2][块3][块4]
在开头插入一段后:
文件 B:  [块1'][块2][块3][块4]      ← 只有块1 变了
```

因此任意位置的编辑只影响附近的 1–2 个块。

纯 Markdown 文本使用**行对齐**策略（边界对齐到换行），这样重复行的表格、日志类内容也能获得良好差分；二进制文件使用 FastCDC 齿轮哈希。

### 2. 传输

每个块以 `hash(内容)` 命名，远端按 `chunks/<前2位>/<hash>` 存放。

同步时：

1. 拉取远端 `index.json`（文件清单：路径 → 版本哈希 + 块列表）
2. 扫描本地（mtime + 大小未变则跳过哈希）
3. 三方比较本地 / 上次同步基线 / 远端
4. **只上传远端缺少的块，只下载本地缺少的块**

### 3. 冲突处理

上次同步成功的状态作为**合并基线**：

```
           本地改?   远端改?   结果
情况 1      是        否       上传本地
情况 2      否        是       下载远端
情况 3      是        是       冲突 → 按覆盖策略选主文件，另一个存副本
```

冲突副本命名：`note.conflict-20240101-120000-windows.md`，两端都会看到。

在插件设置的「高级 → 冲突覆盖策略」中选择「按时间覆盖」或「按大小覆盖」。默认按时间，只有远端晚于本地超过 2 秒才采用远端版本。按大小优先使用字节数较大的版本，大小相同时按时间处理。

### 4. 删除

已跟踪的文件一端删除 → 另一端也删除。

但如果另一端**同时修改**了它，则不会删除——文件会被救回来并给出警告，避免"删除 vs 编辑"导致内容丢失。

## 端到端加密

在设置中打开 **端到端加密**，设置口令后：

- 所有块与索引用 AES-256-GCM 加密后上传
- 块 id 仍是明文的哈希（用于比对差异），但不泄露内容
- 口令**不保存**在任何地方，每次启动需要输入一次

> ⚠️ 口令丢失 = 远端数据永久无法恢复。请把口令存进密码管理器。

加密状态由远端 `meta.json` 决定。切换加密开关需要清空远端同步目录重新开始。

## 安全机制

| 风险 | 防护 |
| --- | --- |
| 远端索引损坏导致本地被清空 | 单次删除超过 25% 且 >5 个文件时中止同步 |
| 两台设备并发写索引互相覆盖 | 条件写入 + 写后校验 + 逐文件合并重试 |
| 两台设备改同一文件 | 冲突副本，双方内容都保留 |
| 下载覆盖本地 | `.diff-sync-history/` 快照 |
| 远端分块损坏 | 每个块下载后校验哈希；文件组装后校验大小 |
| 指向错误的库 | 远端 `meta.json` 记录库 ID，不匹配则拒绝同步 |

## 已知限制

- **仅桌面端**：移动端不支持。
- **周期性极强的内容**（整个文件是同一行重复上万次）差分效果有限——这是内容定义分块的固有盲区，已用行对齐策略缓解。
- **大文件首次同步**需要完整上传一次。
- **WebDAV 条件写入**：部分服务端不实现 `If-Match`（坚果云即如此）。插件会检测并改用写后校验，安全性不降低，但并发时多一次索引读写。
- **坚果云限流**：短时间大量请求会返回 503 并短暂封禁。插件会退避重试，但首次全库同步建议把并发数设为 2 并分批执行。
- 目前不做文件属性/权限同步，只同步文件内容。

## 开发

```
src/
  core/          纯逻辑，不依赖 obsidian，可在 Node 中测试
    chunker.ts   分块算法
    engine.ts    同步引擎（三方合并、差分传输）
    webdav.ts    WebDAV 客户端（传输层可注入）
    remote.ts    远端布局与加密封装
    crypto.ts    AES-GCM + PBKDF2
    manifest.ts  索引与状态的解析/校验
  obsidian/      Obsidian 适配层
    main.ts      插件入口、命令、状态栏
    sync-panel.ts 右侧边栏同步面板
    vault-adapter.ts  Vault ↔ 引擎的 IO 适配
    chunk-cache.ts   磁盘块缓存
    transport.ts     requestUrl 传输（绕过 CORS）
    settings-tab.ts  设置界面
tests/
  dav-server.mjs      测试用 WebDAV 服务器
  run-tests.mjs       核心集成测试（真实 HTTP）
  plugin-load.test.mjs 插件加载测试（stub Obsidian）
  plugin-e2e.test.mjs  真实 bundle 端到端测试
```

核心层没有 `obsidian` 导入，所以测试能直接跑在 Node 里，用的是真实的 HTTP 服务器和磁盘 IO，而不是 mock。

```bash
npm run dev      # 监听构建
npm run build    # 类型检查 + 构建
npm test         # 全部测试
```
